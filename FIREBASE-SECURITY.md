# Сигурност на админ панела

## Какво е направено

- Паролите **никога не се пазят в чист вид**. При създаване на профил паролата се
  преработва с **PBKDF2-SHA256, 150 000 итерации и случайна сол** (Web Crypto API).
  В базата се записват само `salt`, `hash` и `iterations`.
- Сесията се пази в `sessionStorage` и изтича автоматично след **8 часа**.
- Има защита срещу подбор на парола: след **5 грешни опита** входът се блокира за 2 минути.
- Последният администратор не може да бъде изтрит или понижен до редактор.
- Потребителят не може да изтрие собствения си профил.
- Редакторите нямат достъп до секция „Потребители“.

## Важно ограничение (прочети)

Профилите се пазят в Realtime Database, а не във Firebase Authentication. Това означава,
че **проверката на паролата се извършва в браузъра**. Панелът е защитен срещу случаен
посетител, но не и срещу човек, който умишлено реши да пише директно в базата.

Причината: Firebase Authentication изисква ръчно включване на доставчик
„Email/Password“ в Firebase Console, което не може да се направи от кода на сайта.

### Как да го затворим напълно (препоръчително)

1. Firebase Console → **Authentication** → **Sign-in method** → включи **Email/Password**.
2. Authentication → **Users** → **Add user** → създай имейл + парола за всеки администратор.
3. Замени правилата в `database.rules.json` с тези:

```json
{
  "rules": {
    "artists": { ".read": true, ".write": "auth != null" },
    "singles": { ".read": true, ".write": "auth != null" },
    "events":  { ".read": true, ".write": "auth != null" },
    "news":    { ".read": true, ".write": "auth != null" },
    "messages":{ ".read": "auth != null", ".write": true },
    "admin":   { ".read": false, ".write": false }
  }
}
```

4. В `js/auth.js` замени функцията `login()` с `signInWithEmailAndPassword()`
   от Firebase Auth и премахни колекцията `admin/users`.

С тези правила дори при откраднат API ключ никой не може да променя съдържанието
без валиден Firebase акаунт.

## Текущи правила

Файлът `database.rules.json` в репото описва **сегашното** поведение: публично четене
на съдържанието и запис, необходим на админ панела. Коренът на базата е затворен,
така че не се вижда целият дъмп наведнъж.

## Смяна на паролата на първия администратор

Влез в панела → **Моят профил** → смени паролата. Направи го при първото влизане.
